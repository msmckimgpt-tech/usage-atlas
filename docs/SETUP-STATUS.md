0.3.6은 과거 조회 중 추가 크레딧 그래프가 사라지던 압축 경로를 수정합니다. 원본 순번에 고정된 버킷의 극값과 초기화/직전 관측을 보존하고 원본 중단 누계로 연속성을 계산합니다. 최근 기록 앞부분 정리로 환산 기준이 일시 무효화되던 경로도 수정합니다. 남은 학습 원본의 모든 행을 SHA256으로 검증하며 내용 수정·중간 누락·순서·설정 변경은 계속 거부합니다. 이전 캐시는 백그라운드 분석에서 새 검증 정보로 갱신합니다. 실제 원본, 소비량 및 주기 초기화 규칙은 바꾸지 않습니다.

Windows 418 PASS/1 SKIP, WSL 418 PASS/1 SKIP(각 419조건)입니다. WSL은 순차 실행했습니다. 필수 17단계 배포 게이트, 실제 VS Code/CSP, 합성 장기 기록의 사용률·변화량·누적 SVG와 미리보기 렌더 검수가 통과했습니다. Codex·Claude 합성 28,000행으로 초기 소비 후 긴 휴지/주간 초기화, 불규칙 입력·캐시 갱신·재조회·종료 후 재열기를 확인했습니다. 앞부분 정리 후 페이지/미리보기 환산값 일치와 변경된 원본 거부를 호스트 경로에서 확인했습니다. 수집 미제공 한도를 다른 주기로 대신 환산하지 않습니다. 실제 VS Code 검수의 제공자 조회는 0건입니다.

읽기 전용 실제 기록 재계산에서 원본과 누적 소비의 보존 및 압축 후 과거 크레딧 구간 복구를 확인했습니다. 개인 기록과 진단 수치는 공개하지 않습니다. 초기 화면은 장기 조회를 기다리지 않고 저장/조회 작업자를 분리합니다. 창별 2,000점·원장 1,500점 예산을 유지합니다. 합성 50,000행의 첫 조회는 약 1.3–1.5초, 캐시 조회 약 75–93ms, 단일 추가 저장 약 5ms였습니다. 일부 측정은 다른 검수와 동시에 실행했으며 성능 보장 수치가 아닙니다. 300,000행 표본도 제한 내에서 완료했습니다(첫 조회 약 10.4초). 조회 작업자의 JS 힙 표본은 약 122–129MiB였으며 V8 old-generation 한도 128MiB는 전체 JS 힙/RSS 한도가 아닙니다. 이전 압축보다 더 많은 과거 구간을 보존하여 조회 비용은 증가했습니다. 전체 프로세스 RSS와 최대 CPU를 측정한 결과로 해석하지 않습니다. 화면 닫기 시 조회 요청/캐시를 해제하고 유휴 작업자는 종료합니다.

Windows 2개 프로필과 WSL 2개 사용자 설치를 0.3.6로 갱신했습니다. 세 위치의 파일 49개씩과 설정 파일 4개의 해시 보존을 확인했습니다. 원본 DB·기록·로그인을 덮어쓰거나 사용자 창을 강제로 재시작하지 않았습니다. 실행 중인 창은 다시 불러와야 새 코드가 활성화됩니다. npm 의존성과 수집 주기는 0.3.5와 같습니다.

기존 과거 보기 버튼·1년 아카이브·탭 범위 보존과 공개 라이선스 고지를 유지합니다. 실제 원본·DB/WAL/SHM·로그·설정·인증은 공개 소스/VSIX에 포함하지 않습니다. 소스·VSIX 공개 범위를 유지하며 원격 CI·Marketplace 게시·추가 인증은 활성화하지 않았습니다.
