최근 50,000건·파일 제한과 별개로 원본을 로컬 SQLite 아카이브에 기본 365일 보관합니다. Archive Retention Days로 조절하며 만료 일자는 매일 정리합니다. 원본 정리 전에 아카이브 저장을 확인하고 기존 관측 임시 저장/복구 흐름을 유지합니다. 과거 조회는 필요한 범위만 별도 작업자로 처리하고 저장 작업자와 화면 갱신 대기를 분리해 현재 수집을 막지 않습니다. 첫 화면은 아카이브 조회를 기다리지 않습니다. 이미 삭제된 원본은 복원하지 않으며 호출·대화 로그와 최근 기록 내보내기의 보관 범위를 확장하지 않습니다.

Windows 415 PASS/1 SKIP, WSL 415 PASS/1 SKIP(총 416조건)입니다. WSL은 순차 실행했습니다. 필수 17단계 배포 게이트와 실제 VS Code/CSP 검수가 통과했습니다. 실제 VS Code 검수는 최근 파일에 없는 합성 120일 전 아카이브를 버튼으로 읽고 탭 3회 전환·숨김 중 갱신·반복 열기·닫아 새로 열기의 기본 범위를 확인했습니다. 제공자 조회는 0건입니다. 화면 검수는 달력 단위 확장·키보드·보관 경계·로딩/실패 복구·범위/차트 배치 보존·상태 재생성도 확인했습니다.

원본·초기화·최고값 회복·누적·크레딧·금액 계산은 같은 연속 계산 경로를 사용합니다. 단일 행 및 불규칙 묶음의 결과를 전체 투영과 비교했습니다. 과거 상세 조회는 커서 인근 최대 50,000건으로 제한하고 불완전한 범위를 표시합니다. 구독 환산 근거가 있는 과거 Codex 차감 모드 누락은 기존 합의대로 Standard 가정의 추정으로 구분합니다. 대응 관측이 없는 환산은 만들지 않습니다.

합성 50,000건 표본의 첫 조회는 약 0.74초, 캐시 조회 약 39ms, 단일 추가 저장 약 4.8ms였습니다. 조회 작업자의 JS 힙 표본은 약 59MiB, 상한은 128MiB이며 저장 작업자는 32MiB 상한입니다. 전체 RSS·최대 CPU 또는 다른 환경의 성능을 보장하는 수치는 아닙니다. 화면 닫기 시 조회 요청/캐시를 해제하고 유휴 작업자는 종료합니다.

기존 Windows 2개 프로필과 WSL 2개 사용자 설치를 0.3.5로 갱신했습니다. 세 설치 위치의 파일 49개씩과 설정 파일 4개의 해시 보존을 확인했습니다. 현존 원본이 있는 Windows·WSL 저장소는 초기 아카이브에 복사한 뒤 각 원본 행을 읽어 대조했습니다. 최근 원본 파일과 로그인·설정을 덮어쓰지 않았고 사용자 창을 강제로 재시작하지 않았습니다. 실행 중인 창을 다시 불러와야 새 코드와 계속 보관 기능이 활성화됩니다. Node 내장 모듈을 사용하며 npm 의존성은 0.3.4와 같습니다.

사용자가 선택한 소스·VSIX 공개 범위를 유지합니다. 실제 원본·DB/WAL/SHM·로그·설정·인증 파일은 공개 소스/VSIX에 포함하지 않습니다. docs/workflows 템플릿만 보관하며 원격 CI·Marketplace 게시·자동 배포는 비활성 상태입니다. 추가 권한 요청과 인증 변경은 하지 않았습니다.
